# LocalFinance MCP workflow coverage audit

**Reviewed baseline** `8308c98` on `origin/main`. Compared MCP registration, validation and output handling with the HTTP routes, UI calls, parser contracts, DB services and existing test coverage. This was a static audit. No user database or running application was accessed.

## Recommended PR scope

1. Complete the native import workflows. Add investment and bank previews, inline investment workbook input, and the Splitwise journey from CSV preview through import and match review. Preserve existing bank and investment tool names, payloads and response fields. File previews can accept bounded inline data in read-only mode. Opening a host path requires the corresponding upload permission even for a preview.
2. Add an independent, default-off Splitwise write setting. Importing a group and replacing aliases both reconcile pending entries across groups. Manual confirmations can change reported spending and settlement classifications. Surface those effects in Settings and tool discovery. Require the new permission for imports, alias replacement, link/ignore/reset and settlement confirmation. Preserve old permissions through migration and omitted settings fields, and clear the new permission on revoke, backup/restore and reset following the existing lifecycle. The existing authenticated read channel can expose imported Splitwise records and candidates.
3. Bring the evidence used during those workflows into MCP. Expose the missing transaction filters, latest card bill mode, savings goals and account data-health reads. Provide accurate paging, capped shortlist descriptions and permission-aware source/format discovery.

## Acceptance checks

- Exercise actual MCP SDK calls against disposable SQLite, including discovery plus direct invocation under all combinations of the three permissions. Verify legacy settings upgrade to Splitwise false, status reflects changes, omitted fields preserve preferences, existing sessions lose disallowed tools immediately, and revoke/restore clears all write grants and secrets.
- Exercise both fictional investment workbooks by path and by original base64. Preview leaves every table untouched and omits original sheets, arbitrary holding fields, raw account reference and holder details. Same bytes across transports retain the snapshot ID, null valuations and currency. Invalid paths, unsupported extensions, malformed base64, mixed or absent sources and oversize files fail before writing.
- Compare bank preview and import on native data, explicit registered parser override, password challenge and CSV v1. Compare summary and duplicate counts with the app. Check that errors and both response representations omit full account data, raw passwords, original bytes and host paths. Preserve per-file success/failure, cancellation and aggregate preflight.
- Use a fictional Splitwise CSV and bank fixture to exercise paid-by-other, matched, pending, skipped and uninvolved rows, count scope, reimport and malformed files. Check preview is read-only and only the chosen person is applied. Test status/group filtering before paging, typed integer share, payment evidence, invalid alias/regex, expected-status conflict, amount-difference opt-in, ignore/reset and settlement eligibility. Match app spending totals and unchanged statement amounts. Source permission must be checked before opening a host path.
- For transactions compare totals across pages and amount boundaries for review, personal spending, a shared debit and overlapping statements. Exercise duplicate, amended and subsequent bill cycles with and without the latest flag. Test nested paging at page size one, including full extension lists, complete member aliases, non-overlapping IDs, accurate totals, beyond-final pages and nulls.
- Keep the local-only, token-guarded request boundary and existing response redaction. Run affected Go tests plus frontend validation for changed Settings behavior. Use the repository's synthetic samples and isolated databases throughout.
